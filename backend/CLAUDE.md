# Backend — Control Tower

Python 3.11+ + FastAPI + SQLModel (async SQLAlchemy) + asyncpg, on PostgreSQL 15
+ pgvector. Package manager is **uv**. LLMs via the Anthropic Claude SDK and the
OpenAI SDK (default provider, `settings.openai_chat_model`).

**Multi-tenant SaaS (decided 2026-06-21).** All DB/backend work must be
multi-user aware: `users` table, `user_id` FK on every user-data table,
row-level isolation on every query.

## Architecture

- Routers: `app/api/areas/<domain>.py` for each domain
- Service layer: `app/services/` (finance, insights, notifications have sub-folders; others are direct in routers)
- No `--reload` in Docker — **restart required after any Python edit**: `docker compose restart backend`
- Alembic: always review autogenerated migrations — autogenerate tries to DROP `captures` table (model not imported in env). Strip unrelated drops before `upgrade head`.
- APScheduler jobs: recurring finance post (01:00 UTC), budget alerts (on expense write), anomaly scan (04:00 UTC), weekly digest (Sun 13:30 UTC), bill notifications (03:30 UTC)

### WebSockets

- Handlers: `api/sync.py`, `api/chat.py`, `api/agents.py` (`/ws/sync`, `/ws/chat`, `/ws/agents`)
- Always call `ws_auth(websocket)` BEFORE accepting frames; close with code 1008 on auth failure
- Frontend counterparts: `useChat.ts`, `useNotifications.ts`, `useVaultSync.ts`

### Auth

JWT in an httpOnly SameSite=Strict cookie named **`aios_token`** (`api/auth.py`
sets it, `core/deps.py` reads it). This file and the root `CLAUDE.md` both said
`ct_token` until 2026-08-03 — a leftover from the aios-web → control-tower
rename that never touched the cookie. The cookie name is NOT the project name;
renaming it would sign every existing session out. Google OAuth added 2026-06-21.

## Conventions

- **Async first**: all I/O async (DB, HTTP, file ops)
- **Error handling**: FastAPI `HTTPException` with correct status; log with `logger`
- **Secrets**: `get_settings()` from `app.core.config`; never hardcode
- **DB**: SQLModel schemas; async queries with `async with engine.begin() as conn`
- **SaaS rule**: every user-data table needs `user_id UUID FK → users.id`; queries filter by authenticated user
- **Route order**: literal routes must be declared BEFORE `/{id}` param routes
- **SQLModel tables must use sqlmodel's `Field`** — pydantic's `Field` silently drops `primary_key`

## Critical Gotchas

- **`ENVIRONMENT=production` is load-bearing, not a label.** In `development` the app enables the legacy env-credential login backdoor and `ai_allowed()` returns unlimited — on a public signup page that is uncapped LLM spend on the operator key. `AI_FREE_MONTHLY_CREDITS` is enforced *only* in production.
- **Never key TLS-dependent flags on `ENVIRONMENT`** — cookie `secure=` derives from `settings.allowed_origin.startswith("https://")`. Keying it on `ENVIRONMENT` (as it was) makes login fail *silently* on any production deploy not yet behind TLS: the server returns 200 with a valid `Set-Cookie`, the browser refuses to send it over http, and every later request is anonymous with nothing in the logs.
- **`seed_dummy_data.py` is user-scoped and date-relative** (rewritten 2026-08-10). `python seed_dummy_data.py [--email …] [--list] [--keep]` builds ~2,500 rows across 55 tables for ONE user. Its wipe is `DELETE … WHERE user_id` over an explicit `SEEDED_TABLES` allowlist — **never `Model.__table__.delete()`**, which the old version used and which clears the table for every tenant. Every timestamp is `TODAY - n`, and some rows are dated exactly today on purpose: the dashboards filter on today/this-week/12-weeks, so an absolute-dated fixture renders as an empty product. Categories and `health_food_items` are get-or-create (unique constraints + reference data); everything else is wipe-and-rebuild, so re-running is safe.
- **Production refuses to construct `Settings` on a non-https `ALLOWED_ORIGIN`** (2026-08-10) unless `ALLOW_INSECURE_HTTP=true`. This is the enforcement half of the rule above: deriving cookie `secure=` from the origin scheme is correct, but on its own it means a cleartext deploy just *quietly* ships cleartext JWTs. The escape hatch exists so that is a deliberate choice. `tests/test_config_guards.py` asserts every production guard fires AND that the good config still boots — add both directions when you add a guard.
- **`backend/.dockerignore` must NOT exclude `alembic/`** — `entrypoint.sh` runs `alembic upgrade head` inside the container. Excluding it only appears to work because the dev compose bind-mounts `./backend` over `/app`.
- **No Docker `--reload`**: any Python change → `docker compose restart backend`
- **Push notifications gotcha**: `docker compose restart` does NOT re-read `env_file` — use `docker compose up -d backend` after `.env` changes
- **Alembic autogenerate** tries to DROP `captures` table — always review, strip unrelated drops
- **pgvector**: Docker image must be `pgvector/pgvector:pg15`
- **VaultWriteGuard**: all vault writes go through `is_append_allowed()` / `is_read_allowed()` in `services/vault_sync/writer.py`; never bypass. **Area logs are per-year and matched by PATTERN, not listed as literals** — they were hardcoded to `2026.md` until 2026-08-03, which would have silently appended every 2027 entry to the 2026 file (the stale path stayed on the allowlist, so nothing raised). Build the path with `area_log_path(area)` from `services/chat/tools.py`; never write a year into a path. Regression tests: `tests/test_vault_adversarial.py::test_area_log_path_follows_the_year`.
- **health_logs entry_type CHECK**: allowed values are `gym,weight,food,meal,water,steps,body_fat,sleep,note` — adding a new type needs a migration to update the Postgres CHECK constraint
- **Signup agent-seeding swallows exceptions** — check `api/agents.py` if new users lack the 8 default agents
- **Finance categories are a 2-level DB tree, separated by `kind` (income vs expense)** — no hardcoded category lists. `GET /categories?kind=` filters; the tree auto-seeds defaults per kind on first fetch (`_DEFAULT_CATEGORIES`). **Transactions store `category_id`** (FK to the exact node) **plus a denormalized `category`/`source` = the TOP-LEVEL ancestor name** (so existing by-category reports roll up for free; resolve `category_id` for the subcategory). Resolve via `_resolve_category()` in `api/areas/finance.py`. Deleting a category uncategorizes its transactions. **Account is required** on manual expense/income (422 without it).
- **Finance `logged_at` columns are `TIMESTAMP WITHOUT TIME ZONE`** — asyncpg rejects a tz-aware datetime with `DataError: can't subtract offset-naive and offset-aware`. `api/areas/finance.py` normalizes every `logged_at` via the `NaiveDateTime` annotated type (`AfterValidator(_to_naive_utc)`). Any new datetime field mapping to one of these columns must use it. The frontend's matching obligation is in `frontend/CLAUDE.md`.
- **Pending migration chain** (not yet applied if Docker was down): `c7d2e9f1a3b4` (splits/tags) → `d8e3f0a2b5c6` (habits) → `e9f4a1b3c6d7` (workouts) → `f0a5b2c4d7e8` (foods). Run `alembic upgrade head` to apply.
- **Audit + CMS migration chain** (2026-06-22, single linear head): `h006` (is_admin) → `h007` (oauth_states.user_id) → `h008` (per-user composite uniques) → `h009` (content CMS expansion). Run `alembic upgrade head` to apply.

## Testing

- **Multi-tenant isolation tests** live in `tests/test_isolation.py` (11 tests, "user A can't see user B's rows" for chat/captures/integrations/agents). Keep them green and extend them when adding any user-data endpoint. The harness uses in-memory SQLite (StaticPool) and excludes the pgvector vault tables.
- `test_auth` and `test_api_mappings` are **host-only** — run them with `cd backend && uv run pytest`, not in the Docker suite.
- `test_api_mappings.py` walks the frontend source tree at `frontend/apps/*/src` + `frontend/packages/shared/src` to diff declared vs consumed endpoints. If the frontend layout moves, that path must move with it.
- CI does NOT set `APP_PASSWORD`/`APP_EMAIL`: `tests/conftest.py` uses `os.environ.setdefault(...)` and `test_auth.py` logs in with `testpass`. Setting them in the workflow makes the setdefault a no-op and every auth test 401s.

## Commands

```bash
# Local (not Docker) — run from backend/
uv sync --extra dev
uv run uvicorn app.main:app --host 0.0.0.0 --port 8000
uv run pytest tests/ -q

# Migrations
uv run alembic revision --autogenerate -m "description"
uv run alembic upgrade head

# Docker (preferred) — run from the repo root
docker compose up -d
docker compose restart backend        # After any Python edit
docker compose exec backend alembic upgrade head
docker compose exec backend pytest
```
