## P1 — High

- [x] **P1-1 · WS chat/agents bypass `require_verified`.** *(FIXED: `ws_auth` surfaces `email_verified`; both WS endpoints close 1008 when unverified.)*
  HTTP routers are gated in `backend/app/main.py:297-317`, but `ws_chat` (`:270-279`) and `ws_agents` (`:281-290`) only check `ws_auth` + `ws_entitled`. Unverified signups (auto-logged-in at signup) get full AI over WebSocket — the most abuse-relevant surface. `ws_auth` (`deps.py:86-111`) doesn't surface `email_verified`.

- [x] **P1-2 · Verification token never expires; stored plaintext.** *(FIXED: sha256-hashed storage + 24h TTL via `email_verification_sent_at` (migration `u003`). Old plaintext tokens become unmatchable — users hit resend.)*
  No expiry column or time check (`backend/app/api/auth.py:541-561`; `models/user.py:34-35`), yet the email copy claims "expires in 24 hours" (`services/email.py:21`). Token is also persisted raw + indexed — store a sha256 hash and look up by hash. (Entropy itself is fine: `secrets.token_urlsafe(32)`; single-use invalidation correct.)

- [x] **P1-3 · Non-image chat attachments silently dropped.** *(FIXED: picker restricted to `image/*` incl. drag/paste, toast on rejects. Document support = future feature.)*
  `AssistantChatInput.tsx:141-159` accepts any file (no `accept`, plus drag-drop/paste); `useChat.ts:218-227` uploads it; but both adapters forward only `image/*` (`services/chat/openai_agent.py:96`, `services/chat/agent.py:158`). PDFs/docs/CSVs render a preview and vanish — model never sees them, user never told.
  **Fix:** restrict picker to images OR handle document types; at minimum warn on unsupported types.
