# AIOS Web Project Rules
## Central Memory & Source of Truth
- **ALWAYS refer to `CLAUDE.md` in the project root** before making any architectural or codebase changes. It is the central memory file and source of truth for architecture, conventions, and recent updates.
- **Review `SAAS_IMPLEMENTATION_PLAN.md`** for the roadmap and upcoming features (e.g., Dynamic/Modular Pricing, Engagement features, Synergies, Multi-tenancy).

## Core Architecture & Guidelines
- **Stack**: React 18 + Vite + styled-components + `@ledgr/ui` (Frontend) | Python 3.11+ + FastAPI + SQLModel + PostgreSQL (Backend).
- **Styling**: Tailwind is fully removed. All styling MUST use `styled-components` + `@ledgr/ui` theme tokens. No utility classes.
- **SaaS Isolation**: All user-data tables have a `user_id` FK. All backend queries MUST filter operations by `current_user.id` (or `household_id`) to ensure strict multi-tenant isolation.
- **Backend Workflow**: Hot-reload is disabled in Docker. Run `docker compose restart backend` after any Python code edits.
- **Alembic Migrations**: Always review autogenerated migrations. Autogenerate often tries to drop the `captures` table unnecessarily.
- **Settings Layout**: Any settings page (global or domain-specific) MUST use the standard two-panel layout (`AreaSettingsPage`). Do not build inline settings tabs or custom settings layouts.

## Feature Tracking
- **ALWAYS update `FEATURES.md`** in the project root whenever a new feature is added, modified, or removed. This file must be kept up-to-date automatically as the source of truth for the app's current feature set.
